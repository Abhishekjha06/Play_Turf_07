# Play Turf — Avatar System Redesign (5 Fluffy Mascots)

## Context
Today's avatar system is cosmetic-only: `AvatarPicker.tsx` offers 5 robohash URLs + device upload, "Save" only mutates in-memory state (`updateUserAvatar` in `lib/auth.ts`), nothing persists (no profiles UPDATE path exists anywhere), and non-Google users see a random per-session robohash fallback (`avatar.tsx` line 11). Goal: 5 consistent fluffy plush mascots (`yeti` default, `sky`, `blush`, `mint`, `buddy`), persisted as `profiles.avatar_id`, one centralized avatar component, a new mobile-first `/avatar` selection screen, and global integration — same artwork/sizes/layout/behavior in both themes, colors via existing tokens only.

**Artwork note (per your choice):** no reference image reached me and photoreal 3D isn't possible here — I hand-craft five SVG plush mascots (identical geometry, five palettes: white / pastel blue / pink / mint / cream; fur edge via SVG turbulence, glossy eyes, tiny smile, short limbs, transparent bg) and rasterize to 512px WebP with the existing `sharp` dependency. The config maps IDs → files, so real renders can be dropped in later without code changes.

## Part 1 — Mascot assets
- Author `assets/avatars/svg/{yeti,sky,blush,mint,buddy}.svg` — one shared character template (round oversized body, short arms/legs, ear nubs, lighter belly patch, small glossy black eyes + highlights, tiny curved smile, soft fur silhouette), palette-only differences.
- New `components/scripts/generate_avatars.mjs` (sharp pattern from `convert_images.mjs`): renders each SVG to `assets/avatars/{yetiky,skylyt,blushsy,mintly,budly}.webp` (512×512, transparent, ~quality 90). Run it; keep SVG sources for future edits.
- Note: `@/assets` aliases to the repo-root `assets/` (house pattern used by `seed.ts`), so assets live at `assets/avatars/` — the app-equivalent of the spec's `src/assets/avatars/`.

## Part 2 — Central config + component
- New `src/lib/avatars.ts`: `AVATARS = [{ id: "yeti", name: "Yeti", src }, …]` (static imports), `DEFAULT_AVATAR_ID = "yeti"`, `getAvatarById(id)` (falls back to yeti for unknown/missing).
- New `src/ui/MascotAvatar.tsx`: the single centralized avatar renderer — fixed square container (no layout shift), `loading="lazy" decoding="async"`, `onError` fallback to Yeti, sizes via className. Used everywhere; no per-screen avatar logic.

## Part 3 — Supabase: `profiles.avatar_id`
- `supabase_schema.sql`: add `avatar_id text NOT NULL DEFAULT 'yeti'` to the profiles CREATE TABLE + idempotent `ALTER TABLE public.profiles ADD COLUMN IF NOT EXISTS avatar_id text NOT NULL DEFAULT 'yeti';` (same pattern as `is_admin`/`role`). New root script `supabase_avatar_system.sql` for the live DB (house convention — you run it in the dashboard). Existing RLS policy "Users can update own profile" already covers the write; no duplicate profiles created.
- Read paths widened: `User` type + `avatar_id` (`data/seed.ts`); `lib/api/auth.ts` `me()` select + `normalizeUser` + `verifyOtp`/`adminPasswordSignIn`/`clientLogin` profile selects; `lib/auth.ts` `fetchUserRole` → fetches `role, avatar_id` and threads through `mapAuthUser`/`refreshUser`/listener. Missing/null → `'yeti'`.
- Write path: `updateAvatar(avatarId)` in `lib/api/auth.ts` (Supabase `profiles.update` scoped to own id via auth user) + facade `api.updateAvatar` + rewritten `lib/auth.ts` `updateUserAvatar` (calls the API, updates the in-memory store, emits). Google-OAuth `picture` remains in the data but the mascot is the displayed avatar per spec.

## Part 4 — Choose Avatar screen
- New `src/pages/ChooseAvatar.tsx`: header "Choose Your Avatar", subtitle "Pick a character to represent you on Play Turf.", responsive 2/3-col grid of five cards (large mascot, name, `card-panel` rounded card, tap animation, selected = `border-primary` + checkmark badge), prominent **Save Avatar** button. Single-selection state initialized from the profile (`user.avatar_id`), immediate visual update, saving spinner + success/error toasts, graceful not-signed-in redirect. Colors 100% tokens — identical in both themes.
- Route `/avatar` in `App.tsx` (same protection as other user routes). `More.tsx` gets a "Choose Avatar" entry.

## Part 5 — Global integration + cleanup
- `AppHeader.tsx`: profile button → `navigate("/avatar")`; AvatarPicker dialog removed; header avatar renders `MascotAvatar` (per profile).
- Delete `src/ui/AvatarPicker.tsx` (robohash collection + memory-only save dies with it).
- `ui/avatar.tsx`: robohash `DEFAULT_AVATAR` fallback → Yeti mascot import.
- `OpenGames.tsx` player rows + `OpenGameCard.tsx` host chip: replace raw/broken `<img>` with `MascotAvatar` (fixes currently-empty images for real users; other players without data render the default).
- Surfaces that don't exist today (leaderboards) or show team crests (`TeamAvatar` = cricket teams) are left alone by design.
